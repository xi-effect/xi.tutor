# Загрузка файлов: outcome-события (`file_upload_*`)

Документация **фактической** воронки загрузки файлов на фронтенде. Лимиты размера и бизнес-логика загрузки **не менялись**: аналитика читает те же решения, что и UI (`tryStartUpload` / клиентская проверка аватара / ответ API).

Сводный реестр UI-событий: [`docs/umami-events-svodnoe-opisanie.md`](../umami-events-svodnoe-opisanie.md).

Код: `packages/common.utils/src/productAnalytics/fileUpload.ts` → `beginFileUploadAttempt`.

## Зачем

Понять:

- сколько пользователей вообще пытаются загружать файлы;
- сколько загрузок проходит;
- сколько попыток блокируется из‑за текущего лимита размера;
- где это происходит: материалы, кабинет, доска, прочее;
- image vs остальные типы;
- как часто один пользователь повторяет попытку после `file_too_large`.

**Главная метрика:** уникальные пользователи с `file_upload_rejected` и `reason=file_too_large`.

## Воронка одной попытки

```
пользователь выбрал файл
        │
        ▼
file_upload_attempted
        │
        ├── клиент / API отклонили ──► file_upload_rejected
        └── загрузка на сервер ок ──► file_upload_succeeded
```

Максимум **один исход** на одну осознанную попытку. Не слать повторно из‑за progress, re-render или Strict Mode.

Не путать с UI-кликами (`materials-files-upload-select`, `classroom-files-upload` и т.д.): это clickstream, его не заменяем.

Параллельно по-прежнему может уходить `product_limit_reached` (`limit_type=file_size`) — это отдельное baseline-событие лимитов, не замена воронки.

## События

Все три события — тип **Outcome** (результат обработки выбранного файла), не клик по кнопке. `event_version: 1` добавляет `trackProductEvent`.

### `file_upload_attempted`

**Когда:** пользователь выбрал файл, система начала его обрабатывать (валидация на клиенте или запрос).

| Поле            | Тип    | Значения                                      |
| --------------- | ------ | --------------------------------------------- |
| `source`        | string | `materials` / `classroom` / `board` / `other` |
| `file_category` | string | `image` / `document` / `other`                |
| `size_bucket`   | string | `0_1mb` / `1_5mb` / `5_30mb` / `30mb_plus`    |
| `event_version` | number | `1`                                           |

### `file_upload_succeeded`

**Когда:** файл реально загружен на сервер (успешный ответ upload API). Не после открытия пикера и не после preview.

Те же поля, что у `attempted` (без `reason`).

### `file_upload_rejected`

**Когда:** загрузка не состоялась из‑за ограничения или валидации — в том числе если frontend отсёк файл **до** API.

| Поле            | Тип    | Значения                                                           |
| --------------- | ------ | ------------------------------------------------------------------ |
| `source`        | string | как у `attempted`                                                  |
| `reason`        | string | `file_too_large` / `unsupported_type` / `upload_error` / `unknown` |
| `file_category` | string | как у `attempted`                                                  |
| `size_bucket`   | string | как у `attempted`                                                  |
| `event_version` | number | `1`                                                                |

Особенно важно: файл больше текущего допустимого размера, клиент блокирует до запроса → всё равно `attempted` → `rejected` с `reason=file_too_large`.

## Enum

### `source`

| Значение    | Где                                                                                            |
| ----------- | ---------------------------------------------------------------------------------------------- |
| `materials` | Библиотека файлов на `/materials`                                                              |
| `classroom` | Файлы кабинета (тот же модал загрузки, с `classroomId`)                                        |
| `board`     | Доска: picker, drop, картинка / PDF / аудио / презентация / файл, flip-card, картинка activity |
| `other`     | Редактор заметки; отказ клиента при выборе аватара (профиль / онбординг)                       |

### `file_category`

По MIME и расширению (`getFileCategoryFromFile`). Имя файла в Umami **не** уходит.

- `image` — `image/*` и типичные расширения картинок
- `document` — pdf / office / txt / csv и похожие MIME
- `other` — аудио, видео, неизвестное

Лимиты image vs остальных файлов в продукте разные (`maxImageBytes` / `maxFileBytes`). В аналитике категория берётся из файла, решение «можно / слишком большой» — из того же `tryStartUpload(file, kind)`, что и UI.

### `size_bucket`

Точный размер **не** отправляем. Корзины:

| Корзина     | Байты         |
| ----------- | ------------- |
| `0_1mb`     | ≤ 1 МиБ       |
| `1_5mb`     | ≤ 5 МиБ       |
| `5_30mb`    | ≤ 30 МиБ      |
| `30mb_plus` | больше 30 МиБ |

Не путать с корзинами `product_limit_reached` (`0_5mb` / `5_30mb` / `30mb_plus`) — там старая сетка.

### `reason`

| Значение           | Когда                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------- |
| `file_too_large`   | Клиент: `tryStartUpload` / лимит аватара; API: HTTP 413                                |
| `unsupported_type` | Клиентский whitelist MIME/типа; API: 415 / 422                                         |
| `upload_error`     | Прочий сбой сети/сервера при upload                                                    |
| `unknown`          | Квота хранилища, слишком длинное имя, лимит числа файлов на доске, отмена, пустой файл |

Network Error **не** мапится в `file_too_large` (в отличие от эвристики тостов на доске).

## Где стоит и где нет

Стоит на пользовательском выборе файла в материалах, кабинете, доске и редакторе.

Не дублируем:

- автоматический retry очереди (`useRetryFileQueue`);
- фоновый re-upload при вставке с другой доски;
- скриншоты страниц PDF/презентации как «выбор файла пользователем» в редакторе (upload страницы идёт через `useUploadImage` без этой воронки).

Успешная загрузка аватара после кропа **пока не** в воронке: трекается только клиентский отказ (размер/тип) при выборе файла. Не использовать аватар для метрики успешных загрузок.

## Лимиты: не хардкодить в аналитике

Размер сравнивается тем же кодом, что решает «можно загрузить»:

- `evaluateUpload` / `tryStartUpload` (`common.subscription`) — материалы, кабинет, доска, редактор;
- явные проверки в профиле (5 МиБ) и welcome-аватаре (1 МиБ) — как в UI.

Пока `SUBSCRIPTION_BILLING_ENABLED = false`, `tryStartUpload` на клиенте **не** режет по тарифу: oversized чаще уходит на API и даёт `file_too_large` по 413. Когда биллинг включат, клиентский блок до запроса заработает сам — события не переписывать.

## Privacy

Не отправлять: имя файла, URL, file id, classroom id, точный размер, содержимое, raw error, любые PII.

## Метрики в Umami

| Вопрос                                                         | Как считать                                                                          |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Сколько уникальных пользователей пытались грузить файлы        | Unique visitors по `file_upload_attempted`                                           |
| Сколько успешных загрузок                                      | Count `file_upload_succeeded`                                                        |
| Сколько пользователей хотя бы раз выбрали слишком большой файл | Unique visitors по `file_upload_rejected`, `reason=file_too_large`                   |
| Сколько всего `file_too_large`                                 | Count тех же событий                                                                 |
| Где происходило                                                | фильтр `source`                                                                      |
| Image vs остальные                                             | `file_category`                                                                      |
| Распределение по размеру                                       | `size_bucket` на `attempted` или на `rejected`                                       |
| Повторные попытки после лимита                                 | count `file_upload_rejected` (`file_too_large`) / unique visitors по тому же событию |

Не смешивать `materials-files-upload-select` (клик «выбрать файлы») с `file_upload_attempted` (файл уже выбран и обрабатывается).
