# sovlium — банк заданий по математике: продуктовый MVP

## Цель

Дать репетитору быстрый способ найти готовое математическое задание 5–11 класса, посмотреть ответ/решение и вставить задание на tldraw-доску. Банк должен работать без AI-запроса в момент использования и без обязательного бэкенда.

## Экран банка

Верхняя строка — глобальный поиск. Под ней компактные фильтры:

- класс: 5–11;
- тема / подтема;
- сложность: 1–5 (в UI можно визуально свернуть в «базовая / средняя / повышенная»);
- экзамен: ОГЭ / ЕГЭ базовый / ЕГЭ профиль;
- год экзамена;
- номер задания КИМ;
- тип: вычисление / уравнение / геометрия / вероятность / текстовая задача и т. д.;
- «только избранное».

Поиск и фильтры комбинируются: например, `производная максимум` + «11 класс» + «ЕГЭ профиль».

## Карточка результата

Карточка показывает:

1. класс, тему и подтему;
2. сложность;
3. условие с LaTeX;
4. экзаменационные бейджи вида `ЕГЭ профиль · 2026 · №12`;
5. действия `Вставить на доску`, `Ответ`, `Решение`, `В избранное`.

`foundation`-разметку лучше визуально не выдавать за «точный формат №N». Например: `Полезно для ОГЭ №6`. `direct` можно показывать как обычный экзаменационный бейдж.

## Просмотр задачи

При раскрытии карточки:

- ответ показывается отдельно от решения;
- решение — пошагово;
- подсказки раскрываются по одной;
- если есть `figure`, показывается превью схематического рисунка;
- `Ещё вариант` в первой версии может находить другую задачу с тем же `generator.variantGroupId`; позже — локально создавать новый вариант из генератора.

## Вставка на tldraw-доску

Минимальный вариант:

- текст условия → текстовый/markdown-совместимый shape;
- LaTeX → существующий математический shape/renderer sovlium;
- `figure` → адаптер `MathTaskFigure -> tldraw shapes`;
- элементы группируются, чтобы их можно было перемещать как один блок;
- ответ и решение на доску автоматически **не вставляются**.

Структурированная `figure` намеренно независима от внутреннего JSON tldraw. Это позволит менять реализацию доски без миграции 21 000 задач.

## Избранное и недавние

Для MVP без бэкенда:

- `favoriteTaskIds: string[]` — Zustand persist / localStorage;
- `recentTaskIds` — последние 30 открытых/вставленных задач;
- данные задачи не копировать в localStorage, хранить только стабильные ID.

## Поиск и загрузка данных

При входе в банк:

1. загрузить `search_documents.json.gz`;
2. создать MiniSearch индекс;
3. искать по `topic`, `subtopic`, `skills`, `aliases`, экзаменационным терминам, тегам и условию с разными boost;
4. после выбора карточки загрузить `by_grade/grade-{N}.json.gz`;
5. кешировать загруженный класс до конца сессии.

Так полный объект задачи (решение, hints, figure, generator params) не участвует в глобальном индексе и не расходует память без необходимости.

## Что не входит в MVP

- аккаунтная синхронизация избранного;
- серверный поиск;
- автоматическая выдача ДЗ;
- статистика решения учеником;
- адаптивные рекомендации;
- AI-генерация в момент урока;
- полноценная автоматическая проверка свободного ответа;
- обещание, что каждая `foundation`-связь полностью повторяет формат конкретной линии КИМ.

## Метрики MVP

Минимально полезно отправлять в Umami:

- `math_bank_open`;
- `math_bank_search` — query length + active filters, без необходимости отправлять полный текст запроса;
- `math_task_open` — taskId/topic/grade;
- `math_task_insert_board` и `math_task_insert_note`;
- `math_task_solution_open`;
- `math_task_favorite_toggle`;
- `math_task_next_variant`;
- `math_task_report` — комментарий по заданию (`task_id`, без текста условия).

Главная продуктовая метрика — доля сессий банка, закончившихся `math_task_insert_board` или `math_task_insert_note`, плюс median time от `math_bank_open` до вставки (`time_to_insert_ms`, связь по `session_id`). Реализация: [`docs/analytics/math-bank-events.md`](../../docs/analytics/math-bank-events.md).
